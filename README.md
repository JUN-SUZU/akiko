# あきこ：セットアップ

## ローカルで使う

Node.js 22.12以降（24推奨）、npm、ブラウザーが必要です。初回はインターネットに接続してください。`.env` を作らずに次を実行します。

```bash
./setup.sh
```

依存パッケージ、型チェック、テスト、ビルドを実行し、ローカルモードでサーバーを起動します。`http://localhost:3000/` を開いてください。停止はCtrl+Cです。ローカルモードでは学生IDの本人確認は行いません。

- ビルドだけ実行：`./setup.sh --build-only`
- ビルド済みアプリをローカルで再起動：`AUTH_MODE=local HOST=127.0.0.1 npm start`
- ポート変更：`PORT=4000 ./setup.sh`
- 保存先変更：`DATA_DIR=/path/to/data npm start`（標準は `data/`）
- サブパス配置：`BASE_PATH=/yosano-akiko ./setup.sh`（再起動時も同じBASE_PATHを指定）

## 学生IDとサーバー自動保存

初回アクセス時は学生IDの入力画面が表示されます。`s`＋7桁の半角数字（例：`s1234567`）を入力し、「開始する」を押してください。公開環境では、Cloudflare Accessで確認したメールアドレスに管理者が紐づけたIDだけを受け付けます。入力したIDはCookieに1年間保存され、再読み込み時にもサーバーで紐づけを確認してから復元します。管理者が紐づけを変更・解除すると、保存済みCookieではアクセスできなくなります。

学生IDのCookieには `SameSite=Lax` を設定し、HTTPSでは `Secure` も設定します。ローカルHTTPでもIDを保持できます。履修データ本体は引き続きサーバーに保存し、localStorageは使用しません。

トップページで学類と入学年度を選ぶと、その学生ID・学類・年度の履修データをサーバーから読み込みます。読み込み完了までは編集できず、接続に失敗した場合は「再試行」を押してください。別の端末でも同じID・学類・年度を入力すると、保存したデータを読み込めます。

localStorageは使用しません。以前のlocalStorageデータを自動読み込み・削除することもありません。成績のインポート、授業の追加・削除・予定年度の変更、所属区分の変更、リセット、バックアップの復元は、変更後すぐサーバーへ自動保存されます。手動保存は不要です。画面下部に同期状態が表示されます。

保存リクエストは順番に処理し、保存中に変更した場合は最新の内容を続けて保存します。通信失敗時は未保存データをメモリーに保持し、自動で再試行します。保存完了までアプリ内のページ移動を待機し、未保存のままページを閉じる・再読み込みするとブラウザーの確認が表示されます。サーバーと同期済みになってから終了してください。複数端末から変更した場合は、最後に保存した内容が残ります。

公開環境では学生IDだけではデータを読み込み・更新できません。サーバーは毎回Cloudflare Accessの署名済みJWTを検証し、そのメールアドレスと学生IDの紐づけを確認します。ローカルモードは開発・個人利用専用で、学生IDの認証は行いません。

「設定」の「バックアップを保存」でJSONファイルをダウンロードできます。「バックアップから復元」は同じ学類・年度で行ってください。復元後も自動保存されます。以前の共有キーAPIとサーバー上の共有データは残りますが、新しい画面は学生IDによる自動保存を使用します。

共有・学生データは標準で `data/` に保存され、再起動後も残ります。バックアップにはこのディレクトリをコピーしてください。

## Cloudflare Access で公開する

1. [`.env.example`](.env.example) を `.env` にコピーします。
2. `.env` の `CF_ACCESS_TEAM_DOMAIN`、`CF_ACCESS_AUD`、`PUBLIC_ORIGIN` を実際の値に変更します。`PUBLIC_ORIGIN` は公開URLのオリジンで、末尾にパスを付けません。
3. Cloudflare Access側でサイト全体を保護し、`npm start` または `./setup.sh` で起動します。

```bash
cp .env.example .env
# .env の値を編集してから実行
npm start
```

`npm start` と `npm run student:bind` は `.env` を自動で読み込みます。`./setup.sh` も `.env` があれば公開モードで起動します。シェルで同名の変数を設定している場合は、シェルの値が優先されます。`AUTH_MODE=local and PUBLIC_ORIGIN are both set` と表示されたら、公開利用では `AUTH_MODE=access` に変更してください。`.env` 以外に `AUTH_MODE=local` を設定している場合は、その設定も解除してください。

`CF_ACCESS_TEAM_DOMAIN` はAccessのチームドメイン、`CF_ACCESS_AUD` は対象アプリケーションのAUDタグです。これらがない公開モードではサーバーは起動しません。

### メールアドレスと学生IDの紐づけ

管理者はサーバー上で紐づけを追加・変更・解除できます。メールアドレスは小文字に正規化され、1つの学生IDを複数のメールアドレスに割り当てることはできません。変更はサーバーを再起動せず、次のAPIリクエストから反映されます。

```bash
npm run student:bind -- add student@example.edu s1234567
npm run student:bind -- list
npm run student:bind -- remove student@example.edu
```

対応表は `DATA_DIR/student-bindings.json`（標準は `data/student-bindings.json`）です。直接編集する場合は有効なJSONオブジェクトとして原子的に置き換えてください。例: `{ "student@example.edu": "s1234567" }`。ファイルと保存先ディレクトリは管理者だけが読めるようにしてください。`DATA_DIR` を指定してサーバーを動かす場合、コマンドにも同じ `DATA_DIR` を指定します。

ローカルモードはループバック以外のホストや `PUBLIC_ORIGIN` との併用を拒否します。公開環境では `AUTH_MODE=access` を使用してください。Accessのメールアドレスが変わった場合は、管理者が新しいアドレスに紐づけ直してください。

## 授業検索

「単位チェック」で成績を取り込み、「履修を組む」で計画する年度を選び、授業の「予定に追加」を押します。パソコンではドラッグ&ドロップも使えます。「取る授業」に入れた授業は個別に予定年度を変更できます。時間割と空きコマ判定は表示中の年度に合わせて切り替わり、「TWINSに出力」はその年度の予定だけを出力します。必修と選択の卒業単位の合計は履修画面に表示されます。狭い画面では卒業要件表と授業計画を切り替えられます。

授業名・時限・開講情報は現在読み込んでいる授業データの年度版です。別年度の予定を立てるときは参考情報として扱い、実際の開講状況はTWINSで確認してください。

科目番号、科目名、備考を検索できます。`2019年度以降入学者対象`、`総学3・4組`、`医学` などで授業の対象者を検索できます。

「学類・入学年度に合う授業のみ」は標準で有効です。備考の「医学対象」「情報対象」などの略称・正式名称・学群名を、選択中の学類と照合します。複数学類が列挙されている場合は、そのいずれかに一致する授業を表示します。「情報」は情報科学類、「創成」は情報メディア創成学類、「知識」は知識情報・図書館学類として扱います。

「2019年度以降入学者対象」「2018年度以前入学者対象」などは、選択した入学年度と比較します。境界の年度を含み、平成・令和の年度も西暦に換算します。学類と年度の両方の条件がある場合は、両方に一致する必要があります。対象条件のない授業や解析できない条件は表示します。班・クラス、再履修、留学生、その他の受講条件は備考を確認してください。自動判定を外すにはチェックを解除します。「取る授業」と取得済みの授業はこの条件で隠しません。

## HTTPS

NginxやCaddyなどでHTTPSを終端し、Node.jsへHTTPで転送する場合も利用できます。プロキシが公開ドメインのHostヘッダーを保持していれば、同じホストのHTTPS Originからの保存を許可します。異なるホストのOriginは拒否します。

プロキシがHostヘッダーを内部アドレスに書き換える場合は、`.env` の `PUBLIC_ORIGIN` に公開オリジンを指定してください。設定するURLにはパスを含めません。

例えば公開URLが `https://akiko.xn--estu0hy29d.net` なら、`PUBLIC_ORIGIN=https://akiko.xn--estu0hy29d.net` とします。

変更後はNode.jsサーバーを再起動してください。公開Originを設定した場合は、そのOriginからのリクエストだけを許可します。`X-Forwarded-Host` や `X-Forwarded-Proto` はOriginの許可判定に使用しません。

ブラウザーが信頼する証明書を用意し、次のように起動できます。

```bash
TLS_CERT=/path/to/localhost-cert.pem TLS_KEY=/path/to/localhost-key.pem npm start
```

`https://localhost:3000/` を開きます。`HOST=127.0.0.1` を指定するとローカル端末からのみ接続できます。

## 開発・検証

```bash
npm ci
npm run dev
npm run check
npm run lint
npm run build
npm run test:server
npm run test:access
```

`npm run dev` は画面開発用です。共有APIの検証にはビルド後の `npm start` を利用してください。学生IDによる読み込み・自動保存にはNode.jsサーバーが必要です。GitHub Pagesの静的デプロイだけでは履修画面を利用できません。
